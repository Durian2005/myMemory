# myMemory · 口述记录生成传记系统

> 面向中老年用户的**网页微缩版**应用：把口述录音转成文字，经 AI 整理成传记初稿，再在线编辑并导出文档。
>
> 本仓库收录该项目从**需求分析 → 概要设计 → 详细设计**的完整文档链路，以及可用于演示的界面稿。

## 核心闭环

```
录入口述素材  →  语音转文字  →  AI 润色生成传记初稿  →  在线编辑  →  导出 Word 文档
```

## 关键设计决策

| 决策 | 内容 |
|---|---|
| 数据本地优先 | 记录、音频、文本全部保存在浏览器 IndexedDB，后端**不持久化用户数据** |
| 智能能力后端代理 | 语音识别与 AI 润色统一由自有后端转发，前端不接触任何密钥；后端不可用时降级为「本地录音 + 编辑 + 导出」 |
| 多段口述两级结构 | 拆为 Story（记录）+ Segment（片段），解决单段音频字段无法表达多次录音的问题 |
| 原始文本不可覆盖 | 原始转写文本与 AI 润色文本**分字段存储**，AI 不得改写原文，且不得虚构人物 / 时间 / 地点 / 事件 |
| 文档导出 | 后端直接组装 OOXML 生成 `.docx`，不依赖 Office 组件 |
| 技术栈 | 前端 Vue 3 + Vite + Pinia + TypeScript；后端 ASP.NET Core Minimal API |

## 后端模块与接口

后端拆分为 6 个职责单一的模块，对外暴露 4 个接口：

| 模块 | 职责 |
|---|---|
| B01 素材接入 | 接收音频素材并完成准入校验 |
| B02 语音转写 | 调用外部语音识别，产出原始转写文本 |
| B03 AI 生成 | 由原始转写文本生成传记初稿 |
| B04 文档导出 | 组装 OOXML 生成 DOCX |
| B05 外部服务网关 | 统一封装端点、密钥、超时与重试 |
| B06 服务状态 | 汇报可用性，支撑「本地模式」降级 |

接口：`GET /api/health`、`POST /api/transcriptions`、`POST /api/polish`、`POST /api/exports`，配套 21 个业务错误码（前缀 `MYM_`）。

## 工作方式：AI 草稿 + 人工修订

本项目的文档按「**AI 生成草稿 → 人工审阅、去重、补全、对齐业务**」的方式产出。为保留这一过程，实验 2 的技术方案同时收录了 **AI 原稿**与**人工修改稿**两个版本 —— 两稿技术路线一致，差异体现在颗粒度：AI 稿给出骨架与结论，人工稿补齐决策论证、异常字段、流程细节与验收标准。

UI 设计规范亦保留了 v1.0 → v2.0 的迭代痕迹：v2.0 补齐了排版栅格与交互动作两件套，并**修正了 v1.0 中主按钮对比度的标注错误**（原标注约 4.6:1，实测为 3.49:1，未达 4.5:1；v2.0 将主按钮底色加深后实测 4.95:1）。v1.0 作为历史版本保留在 `docs/04-UI设计规范/历史版本/`。
