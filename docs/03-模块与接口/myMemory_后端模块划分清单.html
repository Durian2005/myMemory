1. 说明

1.1 文档目的

本文档基于《myMemory 口述记录生成传记系统 PRD（人工修改版）》与《myMemory 技术方案与页面原型规划（人工修改稿）》，对系统后端进行模块拆分，输出模块清单、各模块职责描述与模块间的职责边界，作为接口设计、编码实现与联调验收的直接依据。

本文档对应 V 模型中详细设计环节的模块拆分部分，与《标准化 API 接口文档》《UI 设计规范 v2.0》共同构成本阶段的完整交付。

1.2 拆分原则

  1. 职责单一：每个模块只承担一类工作，模块内部高内聚。
  2. 互不重叠：任一职责只归属一个模块，不存在两个模块都能处理同一种输入的情况。
  3. 依赖单向：模块间依赖方向明确且无环，底层模块不反向依赖上层模块。
  4. 最小必要：只保留本项目定位所需的模块，不为"以后可能要"预留模块。
  5. 对齐前序：不新增 PRD 与技术方案中不存在的功能或需求。

1.3 与其他文档的关系

1.4 拆分范围与前提

本项目为轻量化网页微缩版，架构上采用「浏览器本地优先 + 单后端代理」：记录、音频、文本等全部用户数据保存在浏览器 IndexedDB 中，后端不持久化用户数据，只承担两类工作 —— 代理外部智能服务（语音识别、AI 润色）与生成导出文档。

因此本次拆分有两个前提，直接决定了模块数量：

  • 凡属于本地能力的职责（记录的增删改查、音频存储、文本编辑、配额检测）一律不进入后端，避免与前端职责重叠。
  • 不引入本项目定位不需要的模块（用户与权限、支付、审核、运营后台、消息通知等），这些内容在《业务边界清单》中已列为「明确不做」。
拆分范围：本文档只拆分后端模块。前端页面与前端模块划分见《技术方案与页面原型规划（人工修改稿）》第 9 章与《UI 设计规范 v2.0》第 7 章。

3. 各模块职责说明

3.1 B01 素材接入模块（AssetIngest）

项内容
职责接收前端提交的音频二进制与元信息；执行准入校验（是否为空、格式是否在白名单内、大小与时长是否超限）；把校验通过的音频载荷交给转写模块
输入音频二进制（webm / mp3 / wav / m4a）、audioFormat、durationSeconds、segmentId
输出校验通过的音频载荷对象（内存持有，不落盘）
明确不做不做转写；不做音频转码与剪辑；不持久化音频；不生成任何文本
承载接口POST /api/transcriptions（校验阶段）

3.2 B02 语音转写模块（Transcription）

项内容
职责调用外部语音识别能力，把音频载荷转换为中文原始转写文本；控制超时与重试上限；识别「结果为空」并将其作为业务异常返回
输入B01 输出的音频载荷
输出原始转写文本、音频时长、识别引擎标识
明确不做不改写、不润色、不纠错文本；不做说话人分离；不保存音频；不保存文本；不生成传记初稿
承载接口POST /api/transcriptions（转写阶段）
依赖B05 外部服务网关模块

3.3 B03 AI 生成模块（Generation）

项内容
职责接收原始转写文本，调用大模型生成传记初稿；注入「不得虚构人物、时间、地点、事件」的事实约束提示词；执行输出长度与空结果校验
输入sourceText（原始转写文本，只读）、storyTitle、mode（polish 单段润色 / merge 多段合并）
输出润色正文、字数、模型标识、生成时间
明确不做不接触音频；不覆盖或回写原始转写文本；不落盘；不做导出；不做多段排序与合并以外的内容管理
承载接口POST /api/polish
依赖B05 外部服务网关模块

3.4 B04 文档导出模块（Export）

项内容
职责接收标题与正文，组装 OOXML 生成 DOCX 字节流并作为附件返回；负责文件名与字符编码处理
输入title、content、（可选）segments 摘要、exportedAt
输出DOCX 二进制流（Content-Disposition: attachment）
明确不做不做标题与正文的业务校验（校验由前端完成，本模块只保留最后一道防御）；不存储用户内容；不保留服务端副本；不依赖 Office / LibreOffice 组件
承载接口POST /api/exports
依赖无

3.5 B05 外部服务网关模块（UpstreamGateway）

项内容
职责统一封装所有外部服务调用（语音识别、大模型）的端点、密钥、超时、重试与限流策略；对上层提供与业务无关的纯技术通道
输入调用意图（服务类型、载荷）、超时策略
输出外部服务返回的原始响应
明确不做不包含任何业务语义（不认识「片段」「传记」「初稿」）；不向用户输出错误文案；不向前端暴露密钥
承载接口无独立对外接口（对内被 B02 / B03 / B06 调用）
依赖无

3.6 B06 服务状态模块（Health）

项内容
职责汇报后端自身与各外部依赖的可用性，供前端判断是否进入「本地模式」
输入无
输出status、version、capabilities（transcription / generation）、timestamp
明确不做不返回任何用户数据；不做鉴权（本项目为本地单机运行，无账号体系）
承载接口GET /api/health
依赖B05 外部服务网关模块

4. 关键职责边界

4.1 素材接入 / AI 生成 / 文档导出 三者边界

这三个模块是本项目最容易出现职责重叠的位置，因此逐维度列出边界：

维度B01 素材接入B03 AI 生成B04 文档导出
处理对象音频二进制纯文本标题 + 正文文本
是否接触音频是（全系统唯一接触者）否否
是否调用外部服务否是（经 B05）否
是否产生新内容否，只做准入校验是（全系统唯一生成者）否，只做排版组装
是否落盘否否否
失败时用户可感知的结果提示素材不合规，原录音仍保留在本地原始转写文本完整保留，可重试导出不成功，编辑内容不受影响
三者的边界可概括为一句话：B01 决定素材能不能用，B03 决定文字怎么写，B04 决定内容怎么交付。

三者之间不共享任何状态，只通过明确定义的载荷单向传递，因此任一模块失效都不会破坏其他模块已持有的数据。

4.2 易混淆点辨析

更容易出现的一种划分为什么不采用本稿的处理
把转写并入「素材模块」素材模块只做准入校验，不依赖网络；转写必须调用外部服务，两者的失败原因、超时策略与重试方式完全不同拆为 B01 与 B02
把大模型调用单独抽成「模型客户端」并与生成模块并列若单独抽出，它也要理解「润色」「合并」等业务语义，会与 B03 产生职责重叠以「是否理解业务」为界：B03 保留业务语义，B05 只做纯技术通道
把 DOCX 生成并入「AI 生成模块」导出不调用 AI，且在无网络时仍应可用，失败面与 AI 模块完全不同独立为 B04，且不依赖任何模块
把健康检查并入网关模块网关模块要求对上层严格隐藏密钥细节，而健康检查需要对外暴露可用性信息，两者的可见性要求相反拆为 B05 与 B06
在后端增加「记录管理模块」本项目数据本地优先，记录由浏览器 IndexedDB 管理，后端一旦介入存储即与前端职责重叠，并违背隐私设计不设该模块，记录管理完全由前端承担

5.1 业务动作的承载层

本表用于说明需求指定的业务动作在本项目架构中分别由哪一层承载，以及为什么其中一项不产生后端接口。

业务动作承载层涉及模块说明
新建传记项目前端本地无本项目数据本地优先，新建记录是浏览器的本地写入，后端不持久化用户数据，故不产生接口
上传 / 录入口述素材前端采集 + 后端接入B01 → B02 → B05前端负责录音与本地存储；后端只负责素材校验与转写，不保存音频
AI 生成传记初稿后端代理B03 → B05由后端代理调用，前端不接触任何密钥
导出文档后端生成B04由后端组装 OOXML 生成 DOCX，见技术方案 8.3 决策三
说明：「新建传记项目」不产生后端接口，是本项目「数据本地优先、后端不持久化用户数据」这一既定设计决策的直接结果，并非接口设计遗漏。相反，若为它强行增设后端写入接口，将与技术方案 8.3 决策一相冲突。
