myMemory 口述记录生成传记系统（网页微缩版）｜标准化 API 接口文档

1. 说明

1.1 文档目的

本文档定义 myMemory 后端对所有接口的调用契约，逐条给出接口名称、请求方式、接口路径、关键入参、返回参数、业务错误码六项字段，并给出本项目专属的业务错误码表，作为前后端联调、测试与验收的唯一依据。

接口范围与《后端模块划分清单》中的 B01–B06 模块一一对应；接口数量刻意保持精简，因为记录与片段的增删改查全部在浏览器本地完成，不经过后端。

1.2 接口设计约定

  1. RESTful 风格：资源用名词复数，动作用 HTTP 方法表达；不出现 /getXxx、/doXxx 一类动词路径。
  2. 无状态：后端不写 Cookie、不建会话、不持久化任何用户数据；相同输入必得相同结果。
  3. UTF-8：请求与响应统一使用 UTF-8；JSON 接口的 Content-Type 为 application/json。
  4. 业务错误码：不使用通用状态码代替业务语义，每个可预期的失败场景都有专属错误码，且随响应返回面向用户的通俗文案。
  5. 不暴露外部依赖：响应体不得出现第三方服务地址、密钥与用户音频内容。

1.3 接口总览

编号接口名称请求方式接口路径承载模块对应业务动作
I01服务健康检查GET/api/healthB06服务可用性探测（支撑本地模式降级）
I02上传口述素材并转写POST/api/transcriptionsB01 + B02上传 / 录入口述素材

关于「新建传记项目」：该业务动作由前端在浏览器本地完成（写入 IndexedDB），后端不持久化用户数据，因此不设对应接口。详见第 5 章的业务动作对照表。

2. 接口详情

2.1 I01 服务健康检查

字段内容
接口名称服务健康检查
请求方式GET
接口路径/api/health
关键入参无
返回参数status（ok / degraded）、version（后端版本号）、capabilities.transcription（布尔，转写能力是否可用）、capabilities.generation（布尔，生成能力是否可用）、timestamp（服务时间，ISO 8601）
业务错误码MYM_5001 服务内部异常
调用时机前端启动时调用一次，之后每 60 秒轮询一次
幂等性天然幂等

返回示例：

{"status":"ok","version":"1.0.0","capabilities":{"transcription":true,"generation":true},"timestamp":"2026-10-15T19:30:00+08:00"}
降级约定：当 capabilities.transcription 或 capabilities.generation 为 false，或本接口请求失败时，前端进入「本地模式」：录音、编辑、导出照常可用，仅转写与初稿生成入口置灰并说明原因。

2.2 I02 上传口述素材并转写

字段内容
接口名称上传口述素材并转写
请求方式POST
接口路径/api/transcriptions
请求编码multipart/form-data（音频以二进制上传）
关键入参见下方入参表
返回参数见下方返回参数表
业务错误码MYM_1001 / MYM_1002 / MYM_1003 / MYM_1004 / MYM_1005 / MYM_2001 / MYM_2002 / MYM_2003 / MYM_5002
幂等性对同一音频内容与同一 segmentId 的重复请求返回相同结果（服务端按音频指纹缓存）

关键入参

参数名类型必填说明
audiofile是音频二进制，支持 webm / mp3 / wav / m4a；单段不超过 30 分钟
segmentIdstring是片段标识，由前端生成，用于把结果回填到对应片段
storyIdstring是所属记录标识，仅用于日志关联，后端不做持久化
durationSecondsnumber是前端测量的片段时长（秒），用于与识别结果交叉校验
audioFormatstring否音频格式；缺省时由服务端嗅探文件头判断

返回参数

参数名类型说明
segmentIdstring原样返回入参中的片段标识，便于前端定位
transcribedTextstring原始转写文本，保留口语语气；可能为空字符串，此时同时返回 MYM_2003
durationSecondsnumber服务端识别出的音频时长，用于前端核对是否与录音时长一致
enginestring识别引擎标识，仅用于排查，不含服务地址与密钥
finishedAtstring完成时间（ISO 8601）
重要约束：本接口只返回原始转写文本，不做任何润色与改写；返回结果不回写前端已有内容，由前端负责写入本地存储。原始转写文本一旦写入即不可被 AI 覆盖（技术方案 8.4 数据处理原则）。

2.3 I03 生成传记初稿

字段内容
接口名称生成传记初稿（润色 / 多段合并）
请求方式POST
接口路径/api/polish
请求编码application/json
关键入参见下方入参表
返回参数见下方返回参数表
业务错误码MYM_1006 / MYM_1007 / MYM_3001 / MYM_3002 / MYM_3003 / MYM_3004 / MYM_5002
幂等性对同一 sourceText 与同一 mode 返回稳定结果（按文本哈希缓存）

关键入参

参数名类型必填说明
storyIdstring是记录标识，仅用于日志关联
storyTitlestring是记录标题，作为生成时的上下文
sourceTextstring是原始转写文本，本次生成唯一的内容来源
modestring是取值为 polish（单段润色）或 merge（多段合并为完整初稿）
styleHintstring否风格提示；本项目默认不启用，第一版不接受该参数

返回参数

参数名类型说明
polishedTextstring传记初稿正文，可编辑
charCountnumber初稿字数，供前端展示与导出前校验
modelstring模型标识，仅用于排查
generatedAtstring生成时间（ISO 8601）
sourceTextHashstring入参原始文本的哈希值，供前端核对「本次初稿对应的是哪一版原文」
事实约束：本接口的提示词中必须包含「不得虚构人物、时间、地点、事件；无法确定的信息保持原样，不作推测」。返回的 sourceTextHash 用于保证初稿与原文可追溯；若生成内容与原文的事实要素差异过大，返回 MYM_3004，由用户对照原文决定是否采用。

2.4 I04 导出 DOCX 文档

字段内容
接口名称导出 DOCX 文档
请求方式POST
接口路径/api/exports
请求编码application/json
关键入参见下方入参表
返回参数成功时直接返回 DOCX 文件字节流，不返回 JSON：响应头 Content-Type 为 application/vnd.openxmlformats-officedocument.wordprocessingml.document，Content-Disposition 为 attachment，文件名按 UTF-8 编码；失败时返回统一 JSON 错误体
业务错误码MYM_1008 / MYM_1009 / MYM_4001 / MYM_4002 / MYM_5002
幂等性对同一输入产出内容相同的文档（导出时间戳字段除外）

关键入参

参数名类型必填说明
titlestring是传记标题，同时作为导出文件名
contentstring是传记正文（用户在编辑页确认后的内容）
segmentsarray否片段摘要数组，每项含 segmentId 与 durationSeconds，用于在文末附素材清单
exportedAtstring否导出时间，缺省由服务端补为当前时间
内容安全：本接口不落盘、不保留服务端副本；生成完成后立即释放内存中的文档字节流。响应体中的文档内容只来源于本次请求，不读取任何服务端存储。

3. 业务错误码

3.1 编码规则

  • 统一前缀 MYM_（myMemory），后接 4 位数字。
  • 第 1 位表示类别，后 3 位为该类别内的序号：1xxx 输入与素材校验类；2xxx 语音转写类；3xxx AI 生成类；4xxx 文档导出类；5xxx 服务与通用类。
  • 每个错误码固定绑定一个 HTTP 状态码、一条面向用户的中文文案（遵循「原因 + 下一步动作」句式）以及一个「是否建议重试」标记。

3.3 HTTP 状态码使用约定

HTTP语义本项目中的使用场景
200成功正常返回数据或文档字节流
400请求参数错误缺少必填字段、字段类型错误
409状态冲突生成内容疑似偏离原始事实，需用户人工核对
413载荷过大音频或文本超出长度上限
415媒体类型不支持音频格式不在白名单内
422语义校验失败内容为空、无法解码、转写结果为空
429请求过于频繁单位时间内请求次数过多
500服务内部错误未预期异常、文档生成失败
503服务不可用外部依赖不可用、后端服务尚未就绪
504上游超时转写或生成调用超时

4. 通用约定

4.1 超时与重试

接口超时重试上限重试策略
GET /api/health3 秒0不重试，由前端按 60 秒轮询
POST /api/transcriptions90 秒2指数退避 2 秒 / 5 秒；仅对 503 与 504 重试
POST /api/polish60 秒2指数退避 2 秒 / 5 秒；仅对 503 与 504 重试
POST /api/exports20 秒1仅对 500 重试

重试上限到达后，前端按返回的错误码展示提示，并允许用户手动再次触发，不进行无上限自动重试。

4.2 幂等性

  • GET /api/health 天然幂等。
  • 三个 POST 接口对同一输入返回稳定结果：转写按音频指纹缓存，生成按 sourceText 哈希缓存，导出按标题与正文哈希缓存。
  • 幂等设计的目的有两个：避免用户重复点击造成重复计费；保证同一素材多次提交得到一致结果，便于对照与排查。

4.3 错误响应体格式

所有失败响应统一返回如下 JSON 结构：

{"code":"MYM_2001","message":"语音转写服务暂时不可用，音频已保存在本地，可稍后重试","detail":"upstream asr returned 503","retryable":true,"requestId":"a1b2c3d4"}
字段类型必返回说明
codestring是业务错误码，取值见第 3 章
messagestring是面向用户的中文说明，遵循「原因 + 下一步动作」句式，可直接展示
detailstring否面向开发者的补充信息；不得包含密钥、外部服务地址与用户音频内容
retryableboolean是是否建议重试，前端据此决定是否显示重试按钮
requestIdstring是单次请求标识，便于对照日志排查

4.4 其他约定

  • 后端无状态：不写 Cookie、不建会话、不落盘用户数据。
  • 不做鉴权：服务仅监听本机回环地址，供同一台机器上的前端调用。
  • 外部服务密钥通过环境变量注入，只出现在 B05 外部服务网关模块中，前端与响应体均不可见。
  • 日志中不得记录音频内容与正文内容，只记录错误码、模块与 requestId。

5. 业务动作与接口对照

业务动作承载层对应接口说明
新建传记项目前端本地无写入浏览器 IndexedDB。后端不持久化用户数据，故不设接口；若强行增设写入接口，将与技术方案 8.3 决策一冲突
上传 / 录入口述素材后端代理POST /api/transcriptions前端采集与本地存储，后端负责校验与转写
AI 生成传记初稿后端代理POST /api/polish由后端代理调用，前端不接触密钥
导出文档后端生成POST /api/exports后端组装 OOXML 生成 DOCX
服务可用性探测后端GET /api/health支撑「本地模式」降级：后端不可用时，录音、编辑、导出仍可正常使用
接口完整性说明：本项目的接口只覆盖「需要外部智能能力或需要生成文件」的动作。记录增删改查、音频存储、文本编辑等全部由浏览器本地承担，因此不产生接口 —— 这是既定架构的结果，不是设计遗漏。
