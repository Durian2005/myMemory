1. 项目概述与目标

1.1 项目背景

myMemory 是一个面向中老年用户的口述记录生成传记系统。用户通过语音讲述人生经历，系统将语音转为文字，再通过 AI 整理为传记初稿，用户可在线编辑并导出文档。

考虑到目标用户打字慢、不熟悉复杂软件，系统以"语音优先、操作简单、数据本地保存"为核心设计原则。

1.2 设计目标

  1. 实现口述录入、语音转写、AI 润色、在线编辑、文档导出的完整闭环。
  2. 用户数据默认保存在本地浏览器，降低隐私风险。
  3. 外部服务（语音识别、AI）统一由后端代理调用，前端不接触密钥。
  4. 语音识别或 AI 不可用时，产品仍可作为本地录音与文本编辑工具使用。

1.3 成功标准

维度标准
功能主流程可完整走通：新建记录 → 录音 → 转写 → 润色 → 编辑 → 导出
可降级关闭后端后，本地录音、编辑与导出仍可用
安全前端与仓库中不存在任何密钥
可用性界面适配中老年用户，操作提示清晰

3. 系统整体架构

3.1 架构风格

系统采用前后端分离的轻量化单体架构，前端为 Vue 3 单页应用，后端为单个 ASP.NET Core Minimal API 服务，不引入微服务与容器编排。

层组成职责
界面层Vue 3 单页应用页面结构、交互与状态展示
状态与业务层Pinia + 服务模块记录与片段状态、流程编排
本地数据层IndexedDB记录、片段、文本的持久化
接口层后端 HTTP 接口（本机回环地址）转写、润色、导出，均为无状态处理
外部服务层语音识别服务、AI 服务仅由后端调用，密钥保存在后端

3.2 数据流

新建记录 → 录音（可多段）→ 语音转文字 → AI 润色生成初稿 → 在线编辑 → 导出 DOCX

记录与片段的增删改查全部在本地完成，只有转写、润色、导出三类操作经后端访问外部服务，后端不持久化用户数据。

3.3 部署与运行

前端构建为静态资源，后端以本机服务形式运行并监听回环地址，两者通过本机端口交互，不部署到公网服务器。

10. 关键流程说明

10.1 端到端主流程

新建记录 → 录音（可多段）→ 语音转文字 → AI 润色生成初稿 → 在线编辑 → 导出 DOCX

任何一步失败都必须保留前序成果，允许用户重试当前步骤而不是回到起点。

10.2 录音流程

  1. 点击"开始录音"，浏览器请求麦克风权限。
  2. 录音中显示状态与已录时长，可暂停与继续。
  3. 结束后生成本地音频对象，可试听并按需重新录制。
  4. 确认后写入本地存储。

10.3 转写与润色流程

  1. 前端将音频发送至后端转写接口，得到原始转写文本。
  2. 提交原始转写文本生成传记初稿。
  3. 页面分区展示原文与润色结果。
技术约束：原始转写文本与润色文本必须分字段存储，润色结果不得覆盖原文；AI 返回内容不得新增原始文本中不存在的人物、时间、地点与事件。

10.4 编辑与导出流程

  1. 进入编辑页修改标题与正文，点击"保存内容"写入本地存储。
  2. 导出前校验标题、正文是否为空以及是否存在未保存修改。
  3. 通过后由后端组装 DOCX，浏览器触发下载。

10.5 异常与恢复原则

异常处理原则
麦克风未授权文字提示重新授权方法，保留当前状态
转写失败保留音频与已有文本，提供重新转写入口
AI 生成失败原始转写文本不丢失，可稍后重试
网络中断本地功能继续可用，提示联网后重试
本地存储不足提示清理或导出后删除旧记录

12. 风险预案

风险影响应对措施
用户口述隐私信息泄露隐私事故，用户信任受损数据默认仅存本地、上传前告知并确认、后端不落盘、提供一键清除入口
语音文件存储异常录音丢失或无法转写录音结束校验非空再落库、配额不足提前提示、转写成功前不删除原音频

浏览器存储被清理记录与音频丢失显式保存反馈、导出提示、清除前二次确认
麦克风权限被拒无法录音文字指引重新授权、提供音频上传备用路径
密钥误入仓库安全事件与费用损失密钥仅存后端环境变量、提交前扫描、只提交示例模板
需求在开发中扩张进度失控以业务边界清单为准

13. 验收标准

  1. 可新建、查看、删除记录，删除前有二次确认。
  2. 可完成一次或多次录音，可暂停、结束、播放与重录。
  3. 刷新页面后记录与音频仍然存在。
  4. 可对音频执行转写，原文不被润色结果覆盖。
  5. 可生成 AI 传记初稿，并支持多段合并。
  6. 可编辑标题与正文并保存。
  7. 可导出可正常打开的 DOCX 文档。
  8. 任一环节失败时已有内容不丢失，并提供重试入口。
