1. 说明

1.1 本规范的作用

本文档是 myMemory 前端开发的唯一视觉与交互基准。所有页面、组件与交互动作都必须严格对齐本规范；实现过程中若发现规范未覆盖的情况，应先补充规范再实现，不得各自即兴决定。

本规范在 v1.0 的基础上做了两处实质性补充：排版栅格由原先只有字号与间距，扩展为完整的列栅格与断点体系；交互动作由原先零散的约束，扩展为按钮、表单、弹窗、错误提示四类交互的完整定义。同时修正了 v1.0 中主按钮对比度标注有误的问题（见 2.6）。

1.2 设计原则

  1. 语音优先：录音是核心动作，在任何相关页面都应是视觉权重最高的元素。
  2. 一页一主操作：每页只允许一个主按钮，其余操作以次级或文字按钮呈现。
  3. 状态可见：任何耗时或状态变化都必须有文字说明，不允许只用颜色或动画表达。
  4. 大而清晰：面向中老年用户，字号、间距与点击区均取下限偏大的取值。
  5. 克制装饰：不使用插画、渐变背景与装饰性动画，避免干扰主流程。
  6. 暖色统一：背景、卡片、按钮、文字、边框全部取自同一低饱和暖色体系。

1.3 四件套总览

本规范按 UI 设计规范的四件套组织，四部分互相独立又彼此约束：

2. 统一配色方案

2.1 配色总则与禁令

全站配色统一采用低饱和度暖色系，由米白、奶油、浅驼、暖木、淡陶土等色构成，营造温馨柔和的视觉氛围。背景、卡片、按钮、文字、边框全部取自同一暖色体系，保持整体协调。

配色禁令：禁止使用大红、大紫等高饱和鲜艳色；禁止夸张渐变、霓虹色与强对比撞色。所有语义色同样以低饱和暖色表达，不引入冷色。

关于「高对比」与「低饱和」的关系：面向中老年用户要求的是对比度高，即前景与背景的明度差足够大；而本规范的约束是饱和度低，即颜色不刺眼。二者并不冲突 —— 本规范通过「深色文字 + 浅色背景」实现高对比，同时所有色相都保持在低饱和的暖色区间内。全部取值均经 WCAG 对比度公式实测，见 2.6。

2.7 色彩使用规则

  • 同一屏内主色（--color-primary）的实心面积占比不超过 10%，避免大面积深色块造成压迫感。
  • 语义色只用于表达状态，不得用于装饰；中性状态一律使用中性色而非语义色。
  • 禁止「浅底 + 浅字」组合：所有文字的对比度都必须满足 2.6 的要求。
  • 页面背景统一为 --color-bg-subtle，卡片与内容区统一为 --color-bg，不得混用。

3.3 表单与输入

  • 输入框高度 56px，左右内边距 16px，边框 1px #E3D8CC，圆角 8px，文字 18px。
  • 标签置于输入框上方，16px / 500，不使用 placeholder 代替标签。
  • 聚焦时边框变 #96604B，并加 2px #96604B 外发光（偏移 2px）。
  • 编辑区为普通文本域，不提供任何富文本工具栏（与技术方案 9.6 一致）。
  • 有字数限制的输入，右侧实时显示计数，如「2 / 40」。
  • 校验失败时，输入框下方显示 16px 错误文字，颜色 #A85A4D，不使用边框变色作为唯一提示。

3.4 表格与卡片

  • 记录卡片：底色 #FDFAF5、12px 圆角、单档投影、内边距 24px；卡片内自上而下固定为「标题 → 更新时间与录音段数 → 状态标签 → 次级操作行」。
  • 记录标题 24px / 700；元信息 16px（不得小于 16px，与 A2 一致），颜色 #6E5F54。
  • 卡片右下提供「继续编辑」次按钮，左侧提供「查看」「删除」文字按钮；删除按钮文字用 #A85A4D。
  • 列表项间距 16px，卡片之间不使用分割线。
  • 数据表格（若后续迭代引入）：表头底色 #EFE4D6，行高不低于 56px，单元格内边距 16px，斑马纹使用 #FDFAF5 与 #F7F1E8 交替。

3.5 状态标签

标签为胶囊形，内边距 4px 12px，字号 16px，采用 2.4 中定义的「浅底 + 深字」组合：已保存（成功）、待转写（中性）、仅录音（中性）、转写失败（危险）、存储不足（警告）。

3.7 弹窗

  • 圆角 16px，内边距 24px，最大宽度 520–632px（跨 8 列）。
  • 结构固定为：标题（22px / 700）→ 说明文字（16px，#6E5F54）→ 按钮区（右下对齐）。
  • 按钮区中，危险操作使用危险按钮，确认操作使用主按钮，取消使用文字按钮或次按钮，最右侧为主操作。
  • 弹窗只使用一档投影 0 1px 2px rgba(61,51,44,.06)，层级靠遮罩与边框表达，不使用多层阴影。

3.8 空态

统一为「一句话说明 + 一个主操作」：不使用插画，文案如「还没有口述记录，可以先创建一条记录」，下方直接给出「新建口述记录」主按钮。

3.9 加载态

列表与详情加载统一使用骨架块（底色 #EFE4D6，圆角 6px），不使用转圈动画；同时给出文字「正在加载…」。

5. 统一交互动作

5.1 交互总则

  1. 任何交互都必须有可感知的反馈；反馈以文字为主、视觉为辅。
  2. 不使用弹跳、旋转、闪烁等夸张动效；全站仅保留 1 处循环动效（录音呼吸圈）。
  3. 单次状态切换的动画时长不超过 200ms。
  4. 尊重系统的「减少动态效果」设置：开启后动画时长归零，功能与状态提示不受影响。

5.7 耗时状态与状态文字

  • 录音中、转写中、生成中、保存中、导出中五类耗时状态，必须在 300ms 内出现文字提示。
  • 任何超过 3 秒的操作，都必须显示进度或「正在进行，请稍候」。
  • 状态文字固定为 16px，位置固定，出现与消失时不得引起页面元素跳动。
  • 状态必须同时可通过文字识别，不得只用颜色或动画表达（对应无障碍检查项 A4）。

8. 交付与命名约定

8.1 实现约定

  • Token 以 CSS 自定义属性形式写入工程主题层，颜色、字号、间距、圆角、投影均引用 Token，不在组件内写死数值。
  • 本规范中的按钮、提示条、卡片、弹窗等元素，映射为前端组件目录下的独立组件，命名遵循技术方案第 5 章的命名规范。

  • 实现完成后按第 7.2 节的检查表逐项复核，作为前端验收的前置条件。

A.3 页面示意

A.3.1 P1 首页 / 记录列表

页面骨架为「顶部栏 64px + 内容区 960px 居中 + 底部动作区 80px」。记录卡片采用 12px 圆角、单档投影与 24px 内边距；状态标签使用 2.4 节的「浅底 + 深字」组合（已保存 / 待转写 / 仅录音）。底部动作区只放唯一主按钮「新建口述记录」，全局页面背景为米白 #F7F1E8，卡片为奶油白 #FDFAF5。

A.3.2 P2 新建记录

表单区跨 8 列（632px），避免单行文字过长影响中老年用户阅读。标签置于输入框上方而非用 placeholder 代替；输入框处于聚焦态时边框转主色并加 2px 外发光；右下角实时显示字数计数。页面下方给出三条使用说明，其中关键信息以深色加粗突出。

A.3.3 P3 录音页

录音圆钮直径 96px、外圈 14px 淡陶土色环，置于内容区视觉中心，是全页权重最高的元素。录音中同时显示状态文字「正在录音 · 00:42」与等宽数字实时时长，不依赖动画单独表意。次级操作（暂停 / 结束本段 / 播放 / 重新录制）统一 48px，视觉权重明显低于圆钮；「播放」在本段未录制完成时置灰。底部动作区的「确认录音」保持禁用，对应「未确认音频前不得自动进入转写」的硬约束。

A.3.4 P4 转写与初稿页

顶部为常驻的失真提示条，用暖琥珀色警示底 + 左侧 4px 竖条实现，不使用红色。转写进度以「进度条 + 文字百分比」双重表达。原始转写文本与 AI 润色文本分为两个独立区块，前者标注「只读 · AI 不可覆盖」，后者标注「AI 生成 · 可编辑」——界面上的分离对应技术方案中两个文本字段的分离存储。

A.3.5 P5 在线编辑页

编辑区为纯文本域，页面上直接标注「不提供加粗 / 不提供列表 / 不提供图片」，把「不使用富文本编辑器」这一约束固化到界面中，避免实现阶段误加工具栏。顶部状态标签显示「有未保存改动」，对应 5.2 节的状态文字化要求。

A.3.6 P6 导出确认

以弹窗形式呈现，遮罩为 rgba(61,51,44,.34)，弹窗宽度跨 8 列。摘要区逐行列出标题、正文字数、录音片段、导出格式与预计文件名，让用户在生成前确认导出范围；主按钮位于弹窗底部右侧，符合 4.5 节的主按钮位置约定。
